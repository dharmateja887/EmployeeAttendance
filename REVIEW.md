# REVIEW.md

Defects found in the starter `app/main.py`. Line numbers refer to the original starter.

| # | Where (function / line) | What is wrong | How you'd notice it | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_overtime` (44-47) | Builds an **aware** `end` (`tzinfo=IST`) but subtracts a **naive** `punch_out` -> `TypeError` on every punch-out (500). Also uses the attendance date, so an overnight shift end is on the wrong day, and it returns any positive minutes instead of applying the 30-minute minimum (R3). | Call `POST /attendance/punch-out`; or an overnight employee gets a 500 / wrong overtime. | Rewrote `compute_overtime_minutes` using aware UTC datetimes, moving the shift end to the next calendar day when `shift_end <= shift_start`, and only counting when `seconds >= 1800`. |
| 2 | `compute_late_minutes` (33-37) | Compares `punch_in` to `shift_start` in whatever timezone the host uses (the timestamps are built with naive local time). Wrong late minutes unless the server is in IST. Overnight punch-ins are attributed to the wrong day. | Run the server with `TZ=UTC`; a 09:31 IST punch reads as many hours early/late. | New `compute_late_minutes(punch_in, attendance_date, shift_start)` converts to IST, anchors the shift on the record's attendance date, and uses integer seconds (`> 600` seconds => floor minutes). |
| 3 | Instants everywhere (35, 46, 102) | Instants are never truncated to whole seconds, and `datetime.fromtimestamp`/`datetime.now()` are used **naive local**. R1 requires truncation and UTC storage; comparison and serialization become host-dependent. | Punch in with `punched_at = ...900` ms; the stored/returned value keeps milliseconds. | All instants pass through `from_millis`/`now_utc`, which produce aware UTC datetimes truncated to seconds. |
| 4 | `compute_work_hours` (40-41) | Uses Python `round()` (half-to-even / float) instead of half-up (R4). | `round(2.675, 2)` -> `2.67`; exact `.xx5` durations round the wrong way. | Uses `Decimal(seconds)/3600` with `ROUND_HALF_UP`. |
| 5 | `create_employee` (77-85) | `datetime.now()` naive local for `created_at`; the response serializes the datetime as an ISO string, not epoch ms; **no unique index**, so concurrent duplicate creates both succeed (check-then-insert race); no `shift_start != shift_end` check; missing field validation. | POST the same `emp_code` twice in parallel -> two 201s; read `created_at` -> a string. | Added a unique index on `employees.emp_code` and catch `DuplicateKeyError` -> 409; `created_at = now_utc()`; response converts to epoch ms; Pydantic patterns + a model validator reject equal shifts and bad input (422). |
| 6 | `list_employees` (88-96) | `skip = page * page_size` skips a whole page (page 1 returns rows 21+). `total` ignores the `department` filter. No sort by `emp_code`. No `page`/`page_size` bounds. `created_at` is an ISO string. | `GET /employees?page=1` misses the first 20; `?department=Sales` reports the global total. | `skip=(page-1)*page_size`; `total` counts the filtered query; `.sort([("emp_code",1)])`; `Query(..., le=100, ge=1)`; epoch-ms output. |
| 7 | `punch_in` (99-121) | No employee check (`emp["shift_start"]` -> `KeyError` -> 500 instead of 404). Naive local time, no truncation. `date` is the local date, not the IST attendance date, and the overnight rule (R1) is missing. `status` is not restricted to presence values. Check-then-insert is racy. Returns a stray `id` field and ISO datetimes. | Punch in an unknown `emp_code` -> 500; two parallel punches -> two records. | Look up the employee (404), use IST R1 date (with overnight rule), validate `status` as `PresenceStatus`, rely on the unique `(emp_code, date)` index and catch `DuplicateKeyError` -> 409, and return the documented record shape. |
| 8 | `list_attendance` (124-150) | Loads **every** matching document into memory and sorts/paginates in Python (fails the ~100k requirement). Sorts only `date` desc (missing `emp_code` asc tiebreak). No `date_from > date_to` check. No status validation or pagination bounds. Stray `id`; ISO datetimes. | `GET /attendance` on 100k docs loads the collection; wrong tie order. | Query-side `.sort([("date",-1),("emp_code",1)]).skip(...).limit(...)`, `count_documents` for `total`, range validation, `Status` enum, bounded pagination, epoch-ms output. |
| 9 | `health` (72-74) | Always returns 200 and never touches MongoDB. | Stop MongoDB; `/health` still says `ok`, so the runner tests against a dead DB. | Pings the server (`admin.command("ping")`) and returns 503 on failure. |
| 10 | module scope (22-23) | No indexes are created, though DATA_MODEL says the seeded DB ships only `_id`. | `explain` on `/attendance` shows `COLLSCAN`. | `ensure_indexes()` runs in a FastAPI lifespan and creates all indexes idempotently (bulk `create_indexes`). |
| 11 | Request models (53-66) | `punched_at: Optional[int]` accepts numeric strings and seconds-looking values; floats and out-of-range values are not rejected. Contract requires strict epoch-ms in `[1e11, 4102444800000]` (422 otherwise). | Send `punched_at: "1783312500000"`, `1783312500` or `...000.0`; all are wrongly accepted. | `EpochMs = Annotated[int, Field(strict=True, ge=..., le=...)]`; non-strict/float/string/second values now 422. |
| 12 | Missing endpoints (153-162) | `punch-out`, `PATCH`, all analytics and `/admin/explain` are absent. | Call any of them -> 404. | Implemented per `openapi.yaml`, analytics as aggregation pipelines. |
| 13 | `punch_in` result `id` (119) | Returns `doc["id"] = str(_id)`, but the contract says records have no id. | Response contains an unexpected `id`. | Removed; records are addressed only by `(emp_code, date)`. |
| 14 | Naive BSON round-trip (22) | `MongoClient(...)` without `tz_aware` silently returns naive datetimes; combined with naive writes, tz bugs stay invisible until the host TZ changes. | Compare a seeded (aware) instant to a freshly computed (naive) one. | Client uses `tz_aware=True`; all boundaries go through explicit UTC conversion. |

## Considered and decided fine

* `compute_late_minutes` returning `0` at exactly 10 minutes past shift start is **correct**: R2 says late only when *strictly more* than 10:00, and the `>` comparison in the starter matched.
* `employees.find(q, {"_id": 0})` projecting out `_id` is correct — the internal id must never leak.
* The `2026-07-06` sample work hours (`9.12`) and the late/overtime samples all reconcile with the corrected helpers.
* `list_attendance`'s use of string `date` ranges (`$gte`/`$lte`) is valid: `YYYY-MM-DD` sorts lexicographically.
* The `PunchInIn.status` default of `PRESENT` matches the contract; only the *validation* of the value was missing.
